# ADR 0002 —— 薄 C++ 移植，而非完整重写

- **状态：** 已接受
- **日期：** 2026-09-04
- **决策者：** 项目所有者

## 背景

作品集面向游戏行业岗位，生产栈是 Unreal/C++（不是 Python）。我们必须证明 AI 是**可迁移**的，但又不把 2–3 个月的预算全花在 C++ 重写上（那样也没时间打磨一个能演示的 demo）。

## 决策

只把**算法价值最高的四个子系统**移植到 C++17——FSM、行为树、A\*、Utility——做成*薄*移植。Steering 和事件总线保持 Python-only。C++ 移植版的正确性，靠**跨语言 parity 测试**（`cpp/src/parity_runner.cpp` + `tests/test_parity.py`）在相同 JSON 输入上验证，而不是靠「功能覆盖广度」。

## 备选方案

- **完整 C++ 重写。** 信号最强，但单人 2–3 个月太慢，会饿死 demo 打磨。**暂否决。**
- **纯 Python + 文档论证可移植。** 省力，但审阅者一句「给我看代码」就能打发。**否决**——我们要可运行的 C++ 证据。
- **C++ 运行时（BehaviorTree.CPP）+ Python 工具。** 最贴近真实工作室分工，但那样核心算法就不是我们展示的了。**推迟**为后续可能的方向。

## 后果

- 好处：可运行的 C++，在 CMake + GoogleTest 下编译；与 Python 逐字节一致；直接回答「这能跑在我们引擎里吗？」。
- 坏处：steering/eventbus 两个子系统是 Python-only，所以 UE 嵌入仍需用 C++ 写这两个（已在 `PORTING_GUIDE.md` 记录）。
- 中性：移植版 API 有意收窄（`AgentView`/`WorldView`）以保持引擎无关——这是刻意的边界，不是缺陷。
