# ADR 0003 —— 共享 JSON schema + parity 作为可移植性契约

- **状态：** 已接受
- **日期：** 2026-09-04
- **决策者：** 项目所有者

## 背景

要让 Python core 和 C++ 移植版*证明*它们是同一个 AI，它们必须消费相同的输入、产出可比的结果。一句「看起来差不多」不是审阅者会信的证据。

## 决策

为地图和行为定义一套**中立 JSON schema**（见 `core/json_defs.py`：`MapDef`、`BehaviorDef`）。两种语言加载*同一份*文件。一个小型 C++ `parity_runner` 输出归一化文本结果（路径如 `x,y;…`、选中的选项名、或最终 FSM 状态）。Python 测试 `tests/test_parity.py` 复现同样的计算并断言字符串一致。这让跨语言等价变成一个**被检查的不变量**，而不是一句声称。

## 备选方案

- **共享二进制 / protobuf。** 更健壮，但多了 codegen 依赖，还削弱「打开文件就能读」的演示故事。**否决。**
- **两种语言各自单测。** 能抓回归，但说明不了两者互相一致。**否决**（不能当唯一防线）。
- **BehaviorTree.CPP XML 当共享格式。** 只对 BT 好用，覆盖不了 A\* 地图或 utility。**否决**当通用契约（在 `PORTING_GUIDE.md` 里保留为选项）。

## 后果

- 好处：审阅者（或 CI）能重新 build C++ 移植版，立刻在具体场景上看到 Python ≡ C++。强而廉价的可移植性证据。
- 好处：JSON schema 同时是 config editor 和无头评估器的输入，场景数据有单一事实来源。
- 坏处：parity 覆盖的是*确定性*子系统（A\*、Utility、单步 FSM）。完整模拟的涌现结果靠评估框架单独比较，不靠字节 parity。
